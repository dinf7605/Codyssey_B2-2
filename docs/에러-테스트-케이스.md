# 에러 주입 테스트 케이스

담당: E. PRD 14.1은 **E-01 / E-03 / E-06 / E-09 통과**를 완료 조건으로 못박았다.
아래는 그 4건을 포함한 전 케이스의 재현 절차다. 실행 결과 스크린샷이 곧 제출물이다.

각 케이스는 두 곳에서 검증한다.
- **참조 구현**: `prototype/` — 빠르고 크레딧을 안 쓴다. 로직 자체의 검증.
- **Make 실기**: 실제 시나리오. 제출용 증거.

## 필수 4종

### T-01 (E-01) RSS 응답 없음 / 타임아웃

| | |
|---|---|
| 주입 방법 | RSS 모듈 URL을 `https://example.invalid/rss.xml`로 임시 변경 |
| 기대 동작 | 5분 간격 2회 재시도 후 시나리오 종료. 무한 반복 없음 |
| 확인 위치 | Make → History → 해당 실행의 재시도 횟수 |
| 통과 기준 | 재시도가 **정확히 2회**에서 멈춤, 상태 = Error, 다음 예약 실행은 정상 |
| 참조 구현 | `python pipeline.py --feed "전자신문"` 상태에서 네트워크를 끊고 실행 → `[2/수집] 실패 → 종료`, 종료 코드 1 |

### T-03 (E-03) 키워드 매칭 0건 — **정상 스킵**

| | |
|---|---|
| 주입 방법 | Filter의 주제 키워드를 `절대없을단어xyz` 하나로 임시 교체 |
| 기대 동작 | 조용히 종료. **알림 없음.** 상태가 Error가 아님 |
| 통과 기준 | Make History 상태 = Success, Notion에 새 행 없음, 알림 0건 |
| 참조 구현 | `prototype/tests/test_pipeline.py::test_no_match_is_normal_skip_not_error` — 종료 코드 **0** |

> 이 케이스의 핵심은 "실패하지 않는 것"이다. 오류로 잡히면 정책 위반이다.

### T-06 (E-06) Gemini API 오류

| | |
|---|---|
| 주입 방법 | HTTP 모듈의 URL 모델명을 `gemini-없는모델`로 변경 (404 유발) |
| 기대 동작 | 2회 재시도 → 실패 → **요약문에 `요약 실패`를 넣고 나머지 필드는 정상 저장** |
| 통과 기준 | Notion에 행이 생성되고 제목/링크/발행일시가 살아 있음 |
| 참조 구현 | `test_summarize.py::test_429_retries_at_most_twice_then_gives_up` |

> 여기서 "저장 자체를 건너뛰게" 만들면 안 된다. 원문 링크를 잃으면 수동 확인도 못 한다.

### T-09 (E-09) Notion 저장 실패

| | |
|---|---|
| 주입 방법 | Notion 모듈의 Database ID 끝자리를 한 글자 바꾼다 |
| 기대 동작 | 2회 재시도 후 종료 + **알림 발생** |
| 통과 기준 | 재시도 2회 확인, 알림 수신 확인 |
