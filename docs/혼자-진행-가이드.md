# 혼자 진행 가이드

> **이 문서는 팀 작업 지침이 아닙니다.** 팀으로 진행할 때는 `docs/조원별-실행가이드.md` 를 보세요.
> 여기는 한 사람이 처음부터 끝까지 다 할 때를 가정한 개인용 진행 순서입니다.

4명이 나눠 하던 걸 한 사람이 할 때의 **순서와 일정**을 정리한 문서입니다.

각 블록의 자세한 설정값과 클릭 경로는 `docs/조원별-실행가이드.md` 에 있습니다.
이 문서는 **"무엇을 어떤 순서로, 며칠에 걸쳐"** 를 다룹니다.

# 1. 혼자 할 때 달라지는 것

## 핵심: 줄일 수 없는 시간이 딱 하나 있다

과제 요건 중 **"7일 연속 자동 실행 성공"** 은 실력으로 압축할 수 없습니다.
7일은 그냥 7일입니다.

나머지(조립, 테스트, 문서)는 밤새워서 하루에 끝낼 수도 있습니다.
그래서 혼자 할 때의 전략은 하나로 정해집니다.

> **최대한 빨리 굴러가게 만들고 스케줄을 켠다.
> 완벽하게 다듬는 건 그게 돌아가는 7일 동안 한다.**

목표: **2일차 저녁에 스케줄 ON.**
완성도 70%여도 켭니다. 나머지 30%는 8일차까지 시간이 남아돕니다.

## 팀으로 할 때와 비교

| | 팀 (4명) | 혼자 |
|---|---|---|
| 계정 준비 | 3명이 동시에 | 순서대로, 1시간 |
| 블록 만들기 | 병렬 → 합치기 | 앞에서 뒤로 한 줄로 |
| 서로 설명하기 | 주 2회 세션 | 불필요 |
| "왜 그렇게 했나" 기록 | 서로 물어보다 남음 | **의식적으로 안 하면 안 남음** ← 함정 |
| 크레딧 | 4명이 나눠 씀 | 전부 내 예산 |
| 조립 사고 | 남의 블록이라 조심 | 내 것이라 막 고치다 꼬임 |

# 2. 전체 일정

| 언제 | 무엇을 | 걸리는 시간 |
|---|---|---|
| **0일차** | 계정 3개 만들기 (Make / Gemini / Notion) | 1시간 |
| **1일차** | 블록 12개 조립 → 처음부터 끝까지 1번 성공 | 3~4시간 |
| **2일차** | 에러 대응 붙이기 → **스케줄 ON** | 1시간 |
| 3~4일차 | 고장 테스트 10가지 (**복제본에서**) | 2시간 |
| 5~6일차 | README, 프롬프트 이력, 스크린샷 정리 | 2시간 |
| 7~8일차 | 보너스 과제, 여유분 | — |
| 9일차 | **7일 치 실행 기록 확보 완료** → 제출 | 1시간 |

총 **12~15시간** 정도입니다. 3~9일차는 매일 아침 **30초**만 씁니다(기록 스크린샷 1장).

## 일정이 밀렸을 때

7일 카운트만 지키면 됩니다. 다른 건 다 뒤로 미룰 수 있습니다.

- 2일차에 못 켰다 → **3일차에는 무조건 켠다.** 완성도를 포기하고라도 켭니다.
- 요약 품질이 마음에 안 든다 → **켜놓고 고칩니다.** 돌아가는 중에도 프롬프트는 수정 가능합니다.
- 문서를 아직 못 썼다 → 7일 돌아가는 동안 쓰면 됩니다.

### 필터를 만들기 전에 알아야 할 것 두 가지

**① 필터는 블록이 아니라 "선 위에 얹는 것"입니다.**
그래서 **뒤에 올 블록을 먼저 만들어야** 필터를 만들 수 있습니다.
실제 작업 순서는 `[4] 만들기 → [3] 필터 → [6] 만들기 → [5] 필터` 가 됩니다.

**② Make의 OR는 조건을 더하는 게 아니라 그룹을 나눕니다.**
```
전체 판정 = (그룹1의 조건 전부 AND) OR (그룹2의 조건 전부 AND) OR ...
```
그래서 **제외 조건을 모든 그룹에 빠짐없이 반복**해야 합니다.
안 그러면 제외 그룹만 참이어도 통과해서 아무 기사나 다 흘러갑니다.

### [3] 🔧 필터 "주제 매칭"

`[2]` 와 `[4]` 사이의 렌치. 그룹 2개, 각 그룹에 6줄씩.

**그룹 1 — 핵심 키워드를 제목에서만**
```
{{2.title}}  Text: Does not contain  광고
{{2.title}}  Text: Does not contain  협찬
{{2.title}}  Text: Does not contain  이벤트
{{2.title}}  Text: Does not contain  채용
{{2.title}}  Text: Does not contain  프로모션
{{2.title}}  Text: Matches pattern   (?i)(\b(AI|LLM|ChatGPT|Gemini|Claude)\b|인공지능|생성형)
```

**그룹 2** — `Add OR rule` 로 새 그룹을 만들고, 제외 5줄을 **똑같이 다시** 넣은 뒤 마지막 줄만:
```
{{2.title + " " + 2.description}}  Text: Matches pattern  (?i)(머신러닝|딥러닝|반도체|데이터센터|\bGPU\b)
```

> `(?i)` = 대소문자 무시. `\b` = 단어 경계로, `AI`가 `said`·`again` 안에 걸리는 걸 막습니다.
> 한글에는 붙이지 않습니다 — 조사가 붙어(`인공지능이`) 오히려 매칭에 실패합니다.
>
> 그룹을 둘로 나눈 이유: 본문까지 보면 `한국은행 "주가 하방 압력 제한적"` 같은 경제 기사가
> 본문에 "AI"가 한 번 나왔다는 이유로 걸립니다. 핵심 키워드는 제목에서만 봐야 합니다.

### 왜 복제본이 필요한가 (혼자 할 때 특히)

3일차에 할 고장 테스트는 **설정을 일부러 망가뜨리는 작업**입니다.
진짜 시나리오에서 하면 **그날 아침 9시 실행이 실패**하고,
**7일 연속이 거기서 끊깁니다.** 다시 처음부터 7일을 세야 합니다.

팀으로 하면 다른 사람이 눈치채지만, 혼자면 아무도 안 말려줍니다.
**고장 테스트는 무조건 복제본에서.**

> 무료 플랜은 "켜져 있는 시나리오" 2개까지 가능합니다.
> 복제본은 꺼둔 채 `Run once`로만 쓰므로 한도에 걸리지 않습니다.

### README에 반드시 들어가야 하는 것

```markdown
# 기술 뉴스 요약 자동화

## 사용한 도구
Make / Google Gemini API / Notion

## 작업 내역
(혼자 진행한 경우: 날짜별 작업 일지로 대체)

## 수집 키워드와 고른 이유          ← 채점 항목
- 제목만 보는 키워드 vs 본문까지 보는 키워드를 나눈 이유
- 제외 키워드를 둔 이유

## 에러 처리 방침과 그 이유           ← 채점 항목
- "정상적으로 넘어감"과 "오류"를 나눈 이유
- 재시도를 2번으로 제한한 이유
- 요약이 실패해도 저장은 진행하는 이유

## Make 시나리오 구조
(스크린샷)

## 설계와 실제 구현의 차이
- 키워드 매칭을 2단계 → 1단계로 바꾼 이유 (Make 필터의 구조적 제약)
- 해시를 sha1 → md5로 바꾼 이유 (Make에 sha1 함수 없음)
```

### 🚨 혼자 할 때 가장 위험한 지점

**"왜 그렇게 했는지"를 아무도 안 물어봅니다.**

팀으로 하면 서로 설명하다 자연스럽게 남지만, 혼자면 다 기억한다고 착각하다가
5일 뒤에 하나도 기억나지 않습니다. 채점 항목의 절반이 "이유"입니다.

**대책**: 지금 `작업일지.md` 파일을 하나 만들고, 무언가 정할 때마다
**그 자리에서 한 줄** 적으세요. 나중에 몰아서 쓰려고 하지 마세요.

```
7/29 - guid 있는 ZDNet으로 결정. 전자신문은 description이 한 줄이라 요약이 안 나옴
7/29 - 키워드 2단계 포기. Make 필터가 번들을 하나씩 통과시켜서 "전부 훑고 0건" 판정 불가
7/30 - 재시도 2회로 제한. 무료 한도 방어가 우선이고, 3회 이상은 실익이 없음
```

# 7. 크레딧 관리 (혼자면 전부 내 예산)

무료 플랜은 **월 1,000 오퍼레이션**입니다.

| 언제 | 예상 소모 |
|---|---|
| 1일차 조립 중 (단독 실행 + Run once 2번) | 약 40~60 |
| 2일차 확인 | 약 20 |
| 3~4일차 고장 테스트 10건 | 약 60~100 |
| 7일 자동 실행 | 약 70~100 |
| 예비 (재테스트, 수정) | 약 100 |
| **합계** | **약 300~400** |

여유는 충분하지만 무한하지 않습니다. 3가지만 지키면 됩니다.

1. **로직 확인은 Python으로.** `python pipeline.py --dry-run` 은 크레딧 0입니다.
2. **블록 하나 확인할 땐 `Run this module only`.** 전체 Run once는 12개를 다 씁니다.
3. **개발 중에 스케줄을 켜두지 않기.** (2일차 이후로는 켜두는 게 맞습니다)

현재 사용량 확인: 좌측 하단 조직명 → **Organization** → 사용량 그래프

# 9. 막혔을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 필터 뒤 블록이 아예 실행 안 됨 | 통과한 기사가 0개 | Array aggregator를 끼움 |
| AI 답변이 빈 값 | 배열 번호를 `[0]`으로 씀 | `[1]` 로 (Make는 1부터) |
| AI 답변이 글자 덩어리 하나 | Parse response = No | `Yes` 로 변경 |
| Notion `property does not exist` | 칸 이름 오타 | Notion 화면과 한 글자도 다르지 않게 |
| Notion `404 object_not_found` | 통합을 표에 연결 안 함 | 표 `···` → 연결 → 통합 추가 |
| 9시가 아닌 시각에 실행 | 시간대 설정 누락 | 프로필 **과** 조직 둘 다 `Asia/Seoul` |
| 같은 기사가 매일 저장됨 | guid 없는 사이트 + 광고 꼬리표 | guid 있는 사이트로 교체 |
| 주제와 무관한 기사가 전부 통과 | 필터의 OR가 **그룹을 나눈다**는 걸 놓침 | 제외 조건을 **모든 그룹에** 반복 |
| 중복방지키가 항상 링크 해시 | 필드명을 `guid`로 씀 → 빈 값 | Make RSS는 **`id`** |
| 중복인데 두 번 저장 | Sequential processing 꺼짐 | ⚙ 에서 켜기 |
| 발행일시가 하루 전 | 해외 시간 그대로 저장 | `formatDate(...; "Asia/Seoul")` |

더 자세한 내용은 `docs/조원별-실행가이드.md` 9장에 있습니다.
