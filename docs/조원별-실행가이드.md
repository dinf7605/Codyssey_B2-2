# 조원별 실행 가이드 (클릭 단위)

`docs/make-시나리오-명세.md`는 **각 모듈에 무엇을 넣을지**를 정의한다.
이 문서는 **그것을 화면에서 어떻게 만드는지**를 담당자별로 순서대로 적은 것이다.
둘이 어긋나면 명세서가 기준이다.

> 표기 규칙
> - `화면: A → B → C` = 그 순서로 클릭
> - `⛔` = 이걸 빠뜨리면 뒤에서 반드시 터지는 지점
> - Make UI는 버전에 따라 메뉴 이름이 조금씩 다르다. 못 찾으면 괄호 안의 영문 원어로 검색할 것.

---

## 공통 준비 (전원, 5분)

1. Make 로그인 → 우측 상단 프로필 아이콘 → **Profile**
2. **Time zone** → `Asia/Seoul` → Save
   - ⛔ 계정별 설정이다. A만 해서는 소용없고 **4명 전부** 해야 한다.
3. 좌측 메뉴 **Scenarios** → 우측 상단 **Create a new scenario**
   - 이름: `연습-본인이름` (예: `연습-B`)
   - 이게 각자의 **개인 테스트 시나리오**다. 메인 시나리오는 A만 건드린다.
   - ⛔ 메인 시나리오를 둘 이상이 동시에 열면 서로 덮어쓴다. 반드시 개인 시나리오에서 만들고 A가 복사해 간다.
4. 좌측 하단 **Scheduling** 토글이 **OFF**인지 확인 (전원, 매번)
   - 개발 중에 켜져 있으면 매일 09:00에 크레딧이 자동으로 나간다.

### 모듈을 A에게 넘기는 방법

개인 시나리오에서 완성한 모듈을 드래그로 전체 선택 → `Ctrl+C` →
A가 메인 시나리오를 열고 `Ctrl+V`. 설정값이 그대로 따라온다.
(Connection은 따라오지 않을 수 있으니 붙여넣은 뒤 한 번 확인)

# A — 팀장 / 워크플로우 설계

## A-1. 조직 설정 (지금 즉시, 다른 사람이 여기 막혀 있음)

1. 좌측 하단 조직명 클릭 → **Organization** → **Settings**
2. **Time zone** → `Asia/Seoul` → Save
   - 프로필 타임존과 조직 타임존이 **둘 다** Asia/Seoul이어야 09:00이 보장된다. 하나만 맞추고 넘어가는 팀이 여기서 6시간~18시간씩 밀린다.
3. 좌측 메뉴 **Team** → 초대된 3명이 **Member 이상 권한**인지 확인
   - `Operator` 권한이면 시나리오 편집이 안 된다. 최소 `Member`.
4. ⛔ **Billing 권한은 A만.** Organization → Team → 각 멤버 Role에서 확인.

## A-2. 메인 시나리오 생성

1. **Scenarios** → **Create a new scenario** → 이름 `뉴스요약-자동화`
2. 하단 중앙 **⚙ (톱니바퀴)** 또는 우측 상단 `···` → **Settings**
3. **Sequential processing** 체크 → OK
   - ⛔ 이걸 안 켜면 번들이 병렬 처리되면서 중복 체크를 앞질러 저장이 새어 나간다. S3가 깨진다.
4. **Allow storing of Incomplete Executions** 도 체크 권장 (에러 핸들러 테스트 때 로그가 남는다)

## A-3. [1] Schedule 모듈

1. 캔버스 중앙의 큰 `+` 클릭 → 검색창에 `Schedule` 입력 → **Tools** 아래 나오는 것이 아니라, **첫 모듈 좌측의 시계 아이콘**을 쓴다
   - 정확히는: 첫 모듈([2] RSS)을 만든 뒤 그 모듈 좌측 상단에 나타나는 **🕐 시계 아이콘**을 클릭하면 스케줄 설정이 열린다. Make에서 Schedule은 별도 모듈이 아니라 **첫 모듈의 속성**이다.
2. **Run scenario** → `Every day`
3. **Time** → `09:00`
4. **Advanced scheduling** 은 건드리지 않는다
5. ⛔ `Every 15 minutes` 같은 간격 트리거 금지. 하루에 무료 크레딧을 다 태운다.
6. 저장 후 **Scheduling 토글은 OFF로 유지** — M6 시작할 때 켠다.

## A-4. 병합 (B/C/D 모듈이 다 온 뒤)

순서대로 붙여넣고 연결한다. 최종 배치:

```
[1]Schedule → [2]RSS → (필터:주제매칭) → [4]Aggregator → (필터:매칭있음)
  → [6]Set variables → [7]Notion Search → [8]Aggregator → (필터:중복아님)
  → [10]HTTP Gemini → [11]Set variable → [12]Notion Create
```

### [4] Array aggregator 만들기

1. `[2] RSS` 모듈 우측 반원(+) 클릭 → 검색 `Array aggregator` → **Tools > Array aggregator**
2. **Source Module** → `[2] RSS`
3. **Aggregated fields** → `title`, `url`, `dateCreated`, `description`, `guid` 전부 체크
4. ⛔ 이 모듈이 있는 이유: **필터를 통과한 번들이 0개면 뒤 모듈이 아예 실행되지 않는다.** Aggregator만이 입력 0개일 때도 "빈 배열 1개"를 내보낸다. 이게 없으면 "매칭 0건"을 감지하는 것 자체가 불가능하다.

### [8] Array aggregator

동일하게, Source Module만 `[7] Notion`으로.

### 필터 만드는 법 (공통)

1. 두 모듈을 잇는 **선 위의 렌치 아이콘** 클릭 → **Set up a filter**
2. **Label** 입력 (`주제 매칭` / `매칭 있음` / `중복 아님`)
3. **Condition** 좌측 필드에 매핑값, 가운데 연산자, 우측에 비교값
4. 조건 추가:
   - **AND** = 아래 `Add AND rule`
   - **OR** = 우측의 `Add OR rule` (열이 옆으로 늘어남)
5. OK

## A-5. 크레딧 실측 (M1 첫 주)

1. 통합 완료 후 좌측 하단 **Run once** 1회 실행
2. 좌측 메뉴 **History** → 해당 실행 클릭 → **Operations** 수치 확인
3. `docs/make-시나리오-명세.md` 2절 표를 실측값으로 교체
   - 명세 추정: 정상 저장일 10~14 ops / 스킵일 4~6 ops. 이게 맞는지 확인하는 것.

## A-6. M6 일정 (가장 중요)

전체 14일 중 **7일 연속 무인 실행**을 증명해야 한다(S1).
→ **늦어도 7~8일차에 Scheduling을 ON** 해야 한다. 통합을 9일차까지 끌면 요건 증명이 불가능하다.

켤 때: 좌측 하단 **Scheduling 토글 ON** → 다음날부터 매일 **History** 스크린샷 확보.

결과를 이 표로 정리해서 팀에 공유한다.

| 피드 | 열리는가 | guid 있는가 | description 길이 | pubDate 포맷 | 하루 기사량 |
|---|---|---|---|---|---|
| ZDNet Korea | | | | | |
| 전자신문 | | | | | |
| Google News | | | | | |

**선정 기준 (우선순위 순)**
1. ⛔ **guid를 준다** — 없으면 링크 해시로 가야 하고, 추적 파라미터(`utm_*`) 때문에 같은 기사가 매일 저장된다

3. `pubDate`가 표준 포맷(RFC 822)이다
4. AI 관련 기사가 하루 1건 이상 나온다

## B-3. Make [2] RSS 모듈

1. 개인 시나리오에서 `+` → 검색 `RSS` → **RSS** 앱 → **Retrieve RSS feed items**
2. **URL** → B-1에서 확정한 주소
3. **Maximum number of returned items** → `20`
4. 나머지(Filter by date, Include headers 등)는 비워둔다
5. **OK** → 모듈 우클릭 → **Run this module only**
6. 우측에 나오는 **OUTPUT** 버블을 펼쳐서 필드명 확인

⛔ **여기서 다들 헤맨다**: Make RSS 모듈의 출력 필드명은
`link`가 아니라 **`url`**, `pubDate`가 아니라 **`dateCreated`** 다.
`description`, `title`, `guid`는 그대로.

⛔ `dateCreated`는 **문자열이 아니라 이미 Date 타입**이다. 이 사실을 D에게 알려줄 것 —
Notion Date 속성에 그냥 매핑하면 대개 그대로 들어간다.

## B-4. [3] Filter "주제 매칭"

1. `[2] RSS` 우측 반원 클릭 → 일단 아무 모듈이나 붙였다가, 사이의 **렌치 아이콘** 클릭
   (또는 A가 [4]를 붙인 뒤 그 사이에 만든다)
2. **Label**: `주제 매칭`
3. **제외 키워드 5개를 AND로** 추가:

| 좌측 | 연산자 | 우측 |
|---|---|---|
| `{{2.title}}` | Text: Does not contain | `광고` |
| `{{2.title}}` | Text: Does not contain | `협찬` |
| `{{2.title}}` | Text: Does not contain | `이벤트` |
| `{{2.title}}` | Text: Does not contain | `채용` |
| `{{2.title}}` | Text: Does not contain | `프로모션` |

4. **주제 키워드는 OR로** — `Add OR rule` 버튼으로 열을 늘린다:

```
{{toLower(2.title)}}                  Text: contains   ai
{{2.title}}                           Text: contains   인공지능
{{toLower(2.title)}}                  Text: contains   llm
{{2.title}}                           Text: contains   생성형
{{toLower(2.title)}}                  Text: contains   chatgpt
{{toLower(2.title)}}                  Text: contains   gemini
{{toLower(2.title)}}                  Text: contains   claude
{{2.title + " " + 2.description}}     Text: contains   머신러닝
{{2.title + " " + 2.description}}     Text: contains   딥러닝
{{2.title + " " + 2.description}}     Text: contains   반도체
{{2.title + " " + 2.description}}     Text: contains   GPU
{{2.title + " " + 2.description}}     Text: contains   데이터센터
```

- `toLower(...)`는 매핑창 우측의 **함수 탭(f(x))** → **Text and binary functions** 에 있다.
- 영문 키워드는 소문자로 비교해야 `AI`/`ai`/`Ai`를 다 잡는다.

⛔ **이건 PRD 초안과 다르다(의도적).** 참조 구현 `article_filter.py`는
"1순위(제목만) 0건일 때만 2순위(본문까지)"라는 2단계 fallback이지만,
Make Filter는 번들을 하나씩 통과시키는 구조라 "전부 훑고 나서 0건이었는지"를 판단할 수 없다.
**v1은 위처럼 OR 단일 필터로 간다.** 발표 때 "원래 설계는 이렇고 Make 제약 때문에 이렇게 바꿨다"를
설명할 수 있어야 한다 — 이게 감점이 아니라 가점 포인트다.

## C-3. Make에 키 안전하게 넣기

⛔ 모듈 헤더에 키를 직접 타이핑하면 NFR-06 위반이고, **스크린샷에 그대로 찍힌다.**

## C-4. [10] HTTP 모듈

1. 개인 시나리오에서 `+` → 검색 `HTTP` → **HTTP** → **Make a request**
2. 설정:

| 항목 | 값 |
|---|---|
| URL | `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent` |
| Method | `POST` |
| Headers | `Add item` 2개 |
| Body type | `Raw` |
| Content type | `JSON (application/json)` |
| Parse response | **`Yes`** |

Headers:
| Name | Value |
|---|---|
| `Content-Type` | `application/json` |
| `x-goog-api-key` | (Keychain 참조 또는 키) |

3. **Request content** 에 붙여넣기:

```json
{
  "contents": [
    {
      "parts": [
        { "text": "너는 기술 뉴스를 요약하는 편집자야.\n아래 기사를 정확히 3줄 이내로 요약해줘.\n\n규칙:\n- 각 줄은 \"- \"로 시작하는 불릿 형태\n- 각 줄 60자 이내\n- 사실만 전달하고 추측이나 의견을 넣지 말 것\n- 기사에 없는 내용을 만들어내지 말 것\n- 요약 외의 머리말, 맺음말, 설명은 출력하지 말 것\n\n제목: {{6.제목}}\n본문: {{6.본문}}" }
      ]
    }
  ]
}
```

- 단독 테스트 단계에서는 `{{6.제목}}` / `{{6.본문}}` 자리에 실제 기사 텍스트를 직접 써서 돌린다.
  (6번 모듈은 아직 없다. A가 병합할 때 매핑으로 바꾼다.)

4. ⛔ **Parse response = Yes** 를 빼먹으면 응답이 문자열 덩어리로 와서 `10.data.candidates`가 안 잡힌다.

## C-5. 에러 핸들러

1. `[10] HTTP` 모듈 **우클릭** → **Add error handler**
2. 나오는 경로에서 **Break** 선택
3. Break 모듈 클릭 → 설정:
   - **Number of attempts**: `2`
   - **Interval**: `5` 분
4. ⛔ **재시도는 통신 실패 시에만 최대 2회.** 요약이 3줄을 넘었다고 재호출하면 안 된다
   (기사 1건당 AI 호출 1회 — 불변 조건). 3줄 초과는 아래 [11]에서 자른다.

## C-6. [11] Set variable (후처리)

1. `[10]` 우측 반원 → 검색 `Set variable` → **Tools > Set variable**
2. **Variable name**: `요약문`
3. **Variable value**:

```
{{ifempty(join(slice(split(10.data.candidates[1].content.parts[1].text; newline); 0; 3); newline); "요약 실패")}}
```

⛔ **Make 배열 인덱스는 1부터 시작한다.** `candidates[0]`으로 쓰면 조용히 빈 값이 나오고
원인을 못 찾아서 하루를 날린다.

동작: `split`(줄 단위 분해) → `slice(0;3)`(앞 3줄) → `join`(다시 합침) → 비었으면 `"요약 실패"`.
- 3줄 초과를 재호출 없이 잘라내는 것이 **E-07**
- 응답이 비어도 `요약 실패` 문자열로 저장을 진행하는 것이 **E-06**

## D-2. 속성 9개 정의

기본 생성되는 `이름` 속성을 클릭 → 이름을 **`제목`** 으로 변경 (타입 Title 유지).

| 속성명 | 타입 | 만들 때 주의 |
|---|---|---|
| `제목` | 제목(Title) | 기본 속성 이름 변경 |

| `원문 링크` | URL | **공백 포함** — `원문링크` 아님 |
| `발행일시` | 날짜(Date) | ⛔ **시간 포함(Include time) 켜기** |
| `출처` | 선택(Select) | 옵션을 미리 만들어 둘 것 |
| `중복방지키` | 텍스트(Text) | ⛔ Text여야 `equals` 필터가 된다 |
| `수집일시` | 날짜(Date) | 시간 포함 켜기 |
| `감성` | 선택(Select) | 보너스 B2. 긍정/중립/부정 |

⛔ **속성명은 한 글자도 다르면 안 된다.** Notion API는 속성명을 키로 쓴다.
`prototype/notion_store.py`의 `PROP_*` 상수, Make [12] 매핑, 이 표 셋이 전부 같아야 한다.

⛔ `출처` Select 옵션은 **B가 알려준 피드명 문자열 그대로** 미리 만들어 둘 것.
API로 없는 옵션을 보내면 자동 생성되는데, 오타가 나면 `ZDNet Korea`와 `ZDNET Korea`가
별개 옵션으로 쌓인다.

## D-6. 중복방지키 규칙 확정 (B의 답을 받은 뒤)

⛔ **한 번 정하면 절대 바꾸지 않는다.** 바꾸는 순간 과거 저장분과 매칭이 안 돼 전부 중복 저장된다.

- **B가 "guid 있음"이라고 하면** → 명세서 [6]의 식 그대로:
  ```
  {{ifempty(get(first(sort(4.array; desc; dateCreated)); "guid"); md5(get(first(sort(4.array; desc; dateCreated)); "url")))}}
  ```
- **"guid 없음"이면** → 추적 파라미터를 떼고 해시:
  ```
  {{md5(replace(get(first(sort(4.array; desc; dateCreated)); "url"); "/\?utm_.*$/"; ""))}}
  ```

> Make에는 sha1이 없어서 `md5`를 쓴다. 참조 구현은 `sha1[:16]`이다.
> **이건 버그가 아니라 의도된 차이다** — 각 환경 안에서 일관되기만 하면 된다.

## D-7. [6] Set multiple variables

1. `+` → **Tools > Set multiple variables**
2. `Add item` 으로 변수 5개:

| Variable name | Variable value |
|---|---|
| `제목` | `{{get(first(sort(4.array; desc; dateCreated)); "title")}}` |
| `링크` | `{{get(first(sort(4.array; desc; dateCreated)); "url")}}` |
| `본문` | `{{substring(get(first(sort(4.array; desc; dateCreated)); "description"); 0; 4000)}}` |
| `발행일시` | `{{get(first(sort(4.array; desc; dateCreated)); "dateCreated")}}` |
| `중복방지키` | (D-6에서 확정한 식) |

⛔ **`선택기사` 변수를 먼저 만들고 나머지가 그걸 참조하는 방식은 쓰지 말 것.**
Make의 Set multiple variables는 같은 모듈 안에서 방금 만든 변수 참조가 보장되지 않는다.
번거로워도 각 변수가 `first(sort(...))`를 각자 다시 쓴다.

⛔ `sort(...; desc; dateCreated)`를 쓰는 이유: 그냥 `first(4.array)`도 대개 맞지만
그건 **피드의 정렬 습관에 의존하는 것**이라, 피드가 정렬을 바꾸면 조용히 엉뚱한 기사가 선택된다.

2. Database ID 선택 → 아래에 속성 입력칸이 자동으로 뜬다

| Notion 속성 | 매핑 |
|---|---|
| 제목 | `{{6.제목}}` |
| 요약문 | `{{11.요약문}}` |
| 원문 링크 | `{{6.링크}}` |
| 발행일시 | `{{6.발행일시}}` |
| 출처 | 피드명 상수 (예: `ZDNet Korea`) |
| 중복방지키 | `{{6.중복방지키}}` |
| 수집일시 | `{{now}}` |

3. 에러 핸들러: 모듈 우클릭 → **Add error handler** → **Break**, attempts `2`, interval `5분`

### 발행일시가 안 들어갈 때 (R1)

위에서부터 순서대로 시도한다:

```
1차: {{6.발행일시}}
2차: {{formatDate(6.발행일시; "YYYY-MM-DDTHH:mm:ssZ"; "Asia/Seoul")}}
3차: {{parseDate(6.발행일시; "ddd, DD MMM YYYY HH:mm:ss ZZ"; "Asia/Seoul")}}
4차: 속성을 비우고 나머지만 저장 (E-08)
```

대개 1차로 끝난다 — RSS 모듈의 `dateCreated`는 이미 Date 타입이기 때문이다.
2차 이상이 필요한 경우는 ① HTTP+XML 파서로 직접 만들었거나 ② 피드가 비표준 포맷일 때뿐이다.

# 부록. 증상별 원인 (막히면 여기부터)

| 증상 | 원인 | 조치 |
|---|---|---|
| 필터 뒤 모듈이 아예 실행 안 됨 | 통과 번들 0개 → 흐름 종료 | Aggregator를 끼워 빈 배열 1건을 만든다 ([4],[8]) |
| Gemini 응답이 빈 값 | 배열 인덱스를 `[0]`으로 씀 | Make는 **1부터** 시작 |
| Gemini 응답이 통째로 문자열 | Parse response = No | `Yes`로 변경 |
| Notion 400 `property does not exist` | 속성명 오타/변경 | Notion 화면의 속성명과 글자 하나까지 같아야 함 |
| Notion 404 `object_not_found` | 통합을 DB에 연결 안 함 | DB 페이지 → `···` → 연결 → 통합 추가 |
| 09:00이 아닌 시각에 실행 | 프로필/조직 타임존 미설정 | 둘 다 Asia/Seoul |
| 같은 기사가 매일 저장됨 | guid 없는 피드 + 링크 추적 파라미터 | md5 전에 파라미터 제거, 또는 guid 있는 피드로 교체 |
| 중복인데 두 번 저장됨 | Sequential processing 꺼짐 | 시나리오 설정에서 켜기 |
| 발행일시가 하루 전으로 보임 | GMT 피드를 그대로 저장 | `formatDate(...; "Asia/Seoul")` |
