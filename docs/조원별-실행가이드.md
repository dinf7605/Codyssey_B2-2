# 2. Make 용어 7개

Make 화면에 나오는 말들입니다. 이것만 알면 헤매지 않습니다.

| 용어 | 뜻 | 쉽게 말하면 |
|---|---|---|
| **시나리오** (Scenario) | 자동화 하나 | 우리가 만드는 프로그램 전체 |
| **모듈** (Module) | 동그란 블록 하나 | "뉴스 가져오기" 같은 작업 1개 |
| **번들** (Bundle) | 모듈 사이를 흘러가는 데이터 덩어리 | 기사 1개 |
| **매핑** (Mapping) | 앞 모듈의 값을 뒤 모듈에 꽂는 것 | `{{2.title}}` 이렇게 생긴 것 |
| **필터** (Filter) | 블록 사이의 렌치 🔧 아이콘 | 조건에 맞는 번들만 통과시키는 검문소 |
| **Connection** | 외부 서비스 로그인 정보 | Notion·Google 계정 연결 |
| **오퍼레이션** (Operation) | 모듈이 1번 실행될 때마다 1개 소모 | **우리 팀의 통장 잔고. 월 1,000개 무료** |

## 화면 위치

```
┌─────────────────────────────────────────┐
│  좌측 메뉴          │   캔버스(작업 공간)  │
│  · Scenarios       │                     │
│  · Templates       │   ○ ─── ○ ─── ○    │  ← 모듈들
│  · Connections     │      🔧             │  ← 필터
│  · Keys            │                     │
│                    │                     │
├────────────────────┴─────────────────────┤
│ [Run once]  [Scheduling ON/OFF]      [⚙] │  ← 하단 바
└──────────────────────────────────────────┘
```

- **Run once** = 지금 1번 실행 (테스트용)
- **Scheduling** = 매일 자동 실행 켜기/끄기 — **개발 중에는 OFF**
- **⚙** = 시나리오 설정

# 4. A — 팀장 / 전체 조립

> **내가 만드는 것**: 아침 9시 알람 + 팀원들이 만든 블록을 하나로 잇기

2. **Organization** → **Settings**
3. **Time zone** → `Asia/Seoul` → Save

> 왜: 개인 프로필 시간대와 **조직 시간대가 따로** 있습니다. 둘 다 맞춰야 9시가 지켜집니다.
> 한쪽만 맞추고 넘어가서 몇 시간씩 밀리는 팀이 매년 나옵니다.

## STEP 2. 팀원 권한 확인

좌측 메뉴 **Team** → 초대된 사람들의 Role을 봅니다.

- `Member` 이상 → 정상
- `Operator` → **시나리오 편집이 안 됩니다.** `Member`로 바꿔주세요.

## STEP 3. 진짜 시나리오 만들기

1. **Scenarios** → **Create a new scenario**
2. 이름: `뉴스요약-자동화`
3. 하단 **⚙** 클릭 → **Sequential processing** 체크 → OK

## STEP 4. 아침 9시 알람 걸기

Make에는 "Schedule 모듈"이 따로 없습니다. **첫 번째 모듈의 속성**입니다.

1. 첫 모듈(B가 만든 RSS)을 캔버스에 놓습니다
2. 그 모듈 **왼쪽 위에 생기는 🕐 시계 아이콘** 클릭
3. **Run scenario** → `Every day`
4. **Time** → `09:00`
5. **Advanced scheduling** 은 건드리지 않습니다
6. OK → **Scheduling 토글은 아직 OFF로 둡니다**

> `Every 15 minutes` 같은 건 절대 쓰지 마세요. 하루 만에 월 오퍼레이션을 다 씁니다.

## STEP 5. 블록 조립하기

팀원들이 `Ctrl+C`로 넘겨준 블록을 붙여넣고 이 순서로 잇습니다.

```
🕐 → [2]뉴스가져오기 → 🔧주제매칭 → [4]모으기 → 🔧매칭있음
   → [6]값정리 → [7]Notion조회 → [8]모으기 → 🔧중복아님
   → [10]AI요약 → [11]다듬기 → [12]Notion저장
```

숫자는 **모듈 번호**입니다. 각 모듈 위에 작게 표시됩니다.
순서가 달라지면 `{{6.제목}}` 같은 매핑의 숫자도 바꿔야 하니, **이 순서 그대로** 만드세요.

### A가 직접 만드는 블록: "모으기" 2개 (Array aggregator)

**[4]번**
1. `[2] 뉴스가져오기` 오른쪽 반원 `+` 클릭
2. 검색창에 `Array aggregator` → **Tools** 아래의 것 선택
3. **Source Module** → `[2] RSS`
4. **Aggregated fields** → `title`, `url`, `dateCreated`, `description`, **`id`** 전부 체크
   - ⚠️ 목록에 `guid`는 없습니다. Make는 guid를 **`id`** 라는 이름으로 내보냅니다.

**[8]번** — 똑같이 만들되 **Source Module만 `[7] Notion`**

> 이게 왜 필요한가 (중요):
> 필터를 통과한 기사가 **0개면 뒤에 있는 블록이 아예 실행되지 않습니다.**
> 그러면 "오늘은 기사가 없었다"는 걸 기록조차 못 합니다.
> "모으기" 블록은 입력이 0개여도 **빈 상자 1개를 반드시 내보내서** 흐름을 이어줍니다.

### 필터(🔧) 만드는 법

필터는 캔버스에 놓는 동그란 블록이 아니라 **두 블록을 잇는 선 위에 얹는 것**입니다.
그래서 **뒤에 올 블록을 먼저 만들어야** 필터를 만들 수 있습니다.

1. 두 모듈을 잇는 **선 위의 렌치 아이콘** 클릭 → **Set up a filter**
2. **Label**에 이름 입력
3. 조건 3칸: `왼쪽 값` / `연산자` / `비교할 값`
4. 조건 더 넣기
   - **그리고(AND)** → 아래쪽 `Add AND rule`
   - **또는(OR)** → 오른쪽 `Add OR rule`

### 🚨 AND/OR를 오해하면 필터가 아무 일도 안 합니다

Make의 필터는 **OR가 조건을 더하는 게 아니라 그룹을 나눕니다.**

```
전체 판정 = (그룹1의 조건 전부 AND) OR (그룹2의 조건 전부 AND) OR ...
```

`Add OR rule`을 누르면 **새 그룹**이 생깁니다. 그래서 "제외 조건은 AND로, 키워드는 OR로"
넣으면 `(제외조건들) OR (키워드1) OR (키워드2)...` 가 되어 **제외 그룹만 참이어도 통과**합니다.
결과적으로 아무 기사나 다 흘러갑니다.

**규칙: 모든 그룹에 제외 조건을 빠짐없이 반복해서 넣습니다.**

## STEP 1. 뉴스 사이트를 비교한다

Make를 쓰지 않고 컴퓨터에서 먼저 확인합니다. **오퍼레이션이 하나도 안 듭니다.**


```bash

```

후보 전체를 한 번에 비교해서 아래 항목을 표로 뽑아줍니다.
특정 주소만 보려면 뒤에 붙이면 됩니다 — `python check_feed.py https://...`

| 확인 항목 | 무엇을 보나 | 왜 중요한가 |
|---|---|---|
| 주소가 열리나 | `실패` 로 나오면 후보 탈락 | 죽은 주소를 Make에 넣으면 매일 실패 |
| **`guid` 제공** | `20/20건` 이면 좋음 | **가장 중요 (아래 설명)** |
| `description` 평균 | 80자 미만이면 위험 | 짧으면 AI가 요약할 내용이 없음 |
| 날짜 변환 실패 | `0건` 이어야 정상 | 날짜 변환은 이 과제의 단골 사고 |
| 1순위 매칭 | 하루 1건 이상 나오나 | 없으면 매일 빈손 |

> ⚠️ PRD 초안의 1순위였던 **ZDNet Korea는 주소가 404**라 쓸 수 없습니다(2026-07-29 확인).
> 현재 `config.py`에는 **전자신문(1순위) / Google News(백업)** 만 남아 있습니다.

### `guid`가 왜 중요한가

같은 기사를 두 번 저장하지 않으려면 기사마다 **고유 번호**가 필요합니다.
`guid`가 그 번호입니다.

`guid`가 없으면 기사 주소(링크)로 번호를 대신 만드는데, 링크에는 `?utm_source=...` 같은
**광고 추적 꼬리표**가 붙습니다. 이 꼬리표가 매일 바뀌면 같은 기사인데도 다른 기사로 보여서
**매일 중복 저장됩니다.**

> **결론: `guid`를 주는 뉴스 사이트를 고르세요.** 그러면 이 문제가 통째로 사라집니다.

> ⚠️ 이 번호는 **Make 화면에서는 `guid`가 아니라 `id`** 라는 이름으로 나옵니다.
> 확정 피드인 전자신문은 `20260729000137` 형태의 기사 고유번호를 20/20건 제공합니다.

1. 연습 시나리오에서 `+` 클릭
2. 검색창에 `RSS` → **RSS** 앱 → **Retrieve RSS feed items** 선택
3. **URL** → 고른 주소 입력
4. **Maximum number of returned items** → `20`
5. 나머지 칸은 비워둡니다
6. **OK**
7. 모듈 **우클릭** → **Run this module only**
8. 오른쪽에 뜨는 결과 풍선을 펼쳐서 확인

### ⚠️ 여기서 다들 헷갈립니다

Make의 RSS 블록이 내보내는 이름이 예상과 다릅니다.

| 예상한 이름 | Make의 실제 이름 |
|---|---|
| `link` | **`url`** |
| `pubDate` | **`dateCreated`** |
| `guid` | **`id`** |

`title`, `description`은 그대로입니다.

`guid`가 특히 위험합니다. 이름이 틀려도 **에러가 안 나고 빈 값**이 나오기 때문에,
중복방지키가 조용히 링크 해시로 넘어가도 알아채지 못합니다.

또 하나: **`dateCreated`는 글자가 아니라 이미 "날짜 형식"으로 옵니다.**
이건 좋은 소식입니다 — Notion 날짜 칸에 그냥 꽂으면 대개 그대로 들어갑니다. **D에게 알려주세요.**

## STEP 5. AI 기사만 걸러내는 필터

필터는 선 위에 얹는 것이므로, **먼저 `[4] 모으기` 블록을 만든 뒤** 그 사이의 선을 클릭합니다.

`[2]` 와 `[4]` 사이의 **렌치 🔧** → **Set up a filter** → Label: `주제 매칭`

조건은 **그룹 2개, 각 그룹에 6줄씩** 넣습니다.
(왜 제외 조건을 두 번 쓰는지는 4장 "AND/OR를 오해하면" 을 보세요.)

### 5-1. 그룹 1 — 핵심 키워드를 제목에서만 찾기

`Add AND rule` 로 세로로 6줄을 쌓습니다.

| 왼쪽 | 연산자 | 오른쪽 |
|---|---|---|
| `{{2.title}}` | Text: Does not contain | `광고` |
| `{{2.title}}` | Text: Does not contain | `협찬` |
| `{{2.title}}` | Text: Does not contain | `이벤트` |
| `{{2.title}}` | Text: Does not contain | `채용` |
| `{{2.title}}` | Text: Does not contain | `프로모션` |
| `{{2.title}}` | **Text: Matches pattern** | 아래 정규식 |

```
(?i)(\b(AI|LLM|ChatGPT|Gemini|Claude)\b|인공지능|생성형)
```

### 5-2. 그룹 2 — 보조 키워드를 본문까지 넓혀서 찾기

`Add OR rule` 을 눌러 **새 그룹**을 만듭니다.
제외 5줄을 **똑같이 다시 넣고**, 마지막 줄만 바꿉니다.

| 왼쪽 | 연산자 | 오른쪽 |
|---|---|---|
| (제외 5줄 동일) | | |
| `{{2.title + " " + 2.description}}` | **Text: Matches pattern** | 아래 정규식 |

```
(?i)(머신러닝|딥러닝|반도체|데이터센터|\bGPU\b)
```

### 왜 이렇게 하나

- **키워드를 정규식 한 줄로 묶는 이유**: 키워드 하나에 조건 한 줄씩 쓰면 그룹마다 제외 5줄을
  반복해야 해서 조건이 72개가 됩니다. 정규식으로 묶으면 12개로 끝납니다.
- **`(?i)`**: 대소문자를 무시하라는 뜻입니다. `AI`, `ai`, `Ai`를 전부 잡습니다.
- **`\b`(단어 경계)를 영문에만 붙이는 이유**: `AI`는 `said`, `again` 안에도 들어 있어 경계가
  없으면 엉뚱한 기사가 걸립니다. 반대로 한글은 조사가 붙기 때문에(`인공지능이`) 경계를
  요구하면 오히려 매칭에 실패합니다.
- **그룹을 둘로 나눈 이유**: 실제 피드로 확인해보니 `한국은행 "주가 하방 압력 제한적"` 같은
  경제 기사가 본문에 "AI"가 한 번 언급됐다는 이유로 걸렸습니다. 핵심 키워드는 제목에서만
  봐야 주제가 맞는 기사가 잡힙니다.

### 발표 때 물어보면 답해야 하는 것

원래 설계는 "제목 키워드가 하나도 없을 때만 본문까지 찾아본다"는 **2단계** 방식이었습니다.
그런데 Make의 필터는 기사를 **한 개씩** 통과시키는 구조라, "20개를 다 본 뒤에 0개였는지"를
판단할 수가 없습니다. 그래서 **두 그룹을 OR로 합친 1단계**로 바꿨습니다.

이건 실수가 아니라 **도구의 제약을 확인하고 내린 결정**입니다. 발표 때 이렇게 설명하면 가점입니다.
(원래 설계는 `prototype/article_filter.py` 에 그대로 남아 있습니다.)

4. 나온 키를 복사 (`AIza...` 로 시작)

- "무료 크레딧 받기" 같은 버튼을 누르지 않습니다

확인 방법: Google Cloud Console → 해당 프로젝트 → Billing →
`This project has no billing account` 상태면 정상입니다.

## STEP 2. 무료 사용량을 기록해둔다

https://ai.google.dev/gemini-api/docs/rate-limits 에서 **Free tier** 표를 봅니다.

1. 그 화면을 **스크린샷으로 저장**하세요
2. Flash 계열 중 무료 사용량이 있는 최신 모델을 고릅니다
3. `prototype/config.py` 의 `GEMINI_MODEL` 을 그 이름으로 수정
4. `docs/make-시나리오-명세.md` 의 주소에 있는 모델 이름도 같이 수정

> 왜 스크린샷: 무료 한도는 수시로 바뀝니다. "우리가 시작한 시점엔 이랬다"는 근거가 필요합니다.

## STEP 3. 키를 안전하게 보관한다

좌측 메뉴 **Keys**(또는 Keychain) → **Add** → 타입 `API key` → 키 붙여넣기 → 저장

> 왜: 블록에 키를 직접 타이핑하면 **스크린샷에 그대로 찍힙니다.**
> 우리 저장소는 공개(public)라서 한 번 새면 되돌릴 수 없습니다.

## STEP 4. AI 호출 블록 만들기

1. 연습 시나리오에서 `+` → 검색 `HTTP` → **HTTP** → **Make a request**
2. 아래대로 채웁니다

| 칸 | 넣을 값 |
|---|---|
| URL | `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent` |
| Method | `POST` |
| Headers | 아래 표대로 2개 |
| Body type | `Raw` |
| Content type | `JSON (application/json)` |
| **Parse response** | **`Yes`** |

**Headers** — `Add item` 을 두 번 누릅니다.

| Name | Value |
|---|---|
| `Content-Type` | `application/json` |
| `x-goog-api-key` | (STEP 3에서 저장한 키) |

3. **Request content** 칸에 그대로 붙여넣기:

```json
{
  "contents": [
    {
      "parts": [
        { "text": "너는 기술 뉴스를 요약하는 편집자야.\n아래 기사를 정확히 3줄 이내로 요약해줘.\n\n규칙:\n- 각 줄은 \"- \"로 시작하는 불릿 형태\n- 각 줄 60자 이내\n- 사실만 전달하고 추측이나 의견을 넣지 말 것\n- 기사에 없는 내용을 만들어내지 말 것\n- 요약 외의 머리말, 맺음말, 설명은 출력하지 말 것\n\n제목: {{6.제목}}\n본문: {{6.본문}}" }
      ]
    }
  ]
}
```

혼자 연습할 때는 `{{6.제목}}`, `{{6.본문}}` 자리에 실제 기사 내용을 직접 써넣고 돌려보세요.
(6번 블록은 D가 만듭니다. 팀장이 합칠 때 진짜 값으로 바뀝니다.)

### ⚠️ Parse response = Yes

이걸 `No`로 두면 답변이 **글자 덩어리 하나**로 와서 다음 단계에서 값을 못 꺼냅니다.

## STEP 5. 실패했을 때 2번만 다시 시도하게 하기

1. `[10] HTTP` 모듈 **우클릭** → **Add error handler**
2. 새로 생긴 갈래에서 **Break** 선택
3. Break 블록 클릭 → 설정
   - **Number of attempts**: `2`
   - **Interval**: `5` 분

> 재시도는 **통신이 끊겼을 때만** 합니다.
> "요약이 4줄로 왔으니 다시 시켜야지"는 안 됩니다 — 기사 1개당 AI 호출은 **딱 1번**입니다.
> 4줄로 오면 다음 STEP에서 잘라냅니다.

## STEP 6. 답변 다듬기

1. `[10]` 오른쪽 `+` → 검색 `Set variable` → **Tools > Set variable**
2. **Variable name**: `요약문`
3. **Variable value**: 아래를 그대로 붙여넣기

```
{{ifempty(join(slice(split(10.data.candidates[1].content.parts[1].text; newline); 0; 3); newline); "요약 실패")}}
```

읽는 법 (안쪽부터):
1. `split(...; newline)` → 답변을 **줄 단위로 쪼갠다**
2. `slice(...; 0; 3)` → **앞 3줄만** 남긴다
3. `join(...; newline)` → 다시 이어 붙인다
4. `ifempty(...; "요약 실패")` → 결과가 비었으면 `요약 실패`라는 글자를 넣는다

### 🚨 Make는 배열 번호가 1부터입니다

`candidates[1]`, `parts[1]` 입니다. 프로그래밍 습관대로 `[0]` 을 쓰면
**에러도 안 나고 그냥 빈 값**이 나옵니다. 원인을 못 찾아 하루를 버리는 지점입니다.

### 왜 실패해도 "요약 실패"를 넣나

AI가 실패했다고 저장 자체를 건너뛰면, **기사 링크까지 같이 잃습니다.**
그러면 나중에 사람이 직접 확인할 방법도 없어집니다.
요약이 없어도 제목·링크·날짜는 남기는 게 낫다 — 이게 우리 팀의 방침입니다.

   - **이 기록 자체가 제출물입니다.** 최종본만 있으면 안 됩니다.
3. 프롬프트에서 "3줄 이내"를 잠깐 지워 긴 답변을 유도 → 앞 3줄만 남는지 확인 → 문구 되돌리기

## STEP 6. 중복방지키 정하기 (B의 답을 받은 뒤)

기사마다 붙일 **고유 번호**를 만드는 규칙입니다.

**B가 "guid 있다"고 하면** — 이걸 씁니다 (현재 확정 피드가 여기 해당):
```
{{ifempty(get(first(sort(4.array; desc; dateCreated)); "id"); md5(get(first(sort(4.array; desc; dateCreated)); "url")))}}
```

**B가 "guid 없다"고 하면** — 광고 꼬리표를 떼고 씁니다:
```
{{md5(replace(get(first(sort(4.array; desc; dateCreated)); "url"); "/\?utm_.*$/"; ""))}}
```

### 🚨 필드명은 `"guid"`가 아니라 `"id"` 입니다

Make의 RSS 블록은 guid를 **`id`** 라는 이름으로 내보냅니다.
`"guid"`라고 쓰면 **에러 없이 빈 값**이 나오고, `ifempty` 때문에 조용히 링크 해시로
넘어갑니다. 겉으로는 잘 도는 것처럼 보여서 알아채기 어렵습니다.

**확정 전에 실제 값을 한 번 보세요:**
`[2] RSS` 우클릭 → `Run this module only` → OUTPUT에서 `id` 값 확인

| `id` 값 | 판정 |
|---|---|
| `20260729000137` | ✅ 기사 고유번호. 가장 안정적 |
| `https://www.etnews.com/20260729000137` | ✅ 추적 꼬리표가 없으니 이대로 써도 됨 |
| 비어 있음 | ⚠️ 이때만 `md5(url)` 우회가 실제로 작동 |

### 🚨 한 번 정하면 절대 바꾸지 마세요

이 규칙을 바꾸면 **예전에 저장한 기사들과 번호가 안 맞습니다.**
그러면 이미 있는 기사를 "새 기사"로 착각해서 **전부 다시 저장됩니다.**
프로젝트 후반에 이게 터지면 수습이 안 됩니다.

> 참고: 참조 코드는 `sha1`, Make는 `md5`를 씁니다. 다른 게 맞습니다 —
> Make에는 `sha1` 함수가 없습니다. **각자 안에서만 일관되면 됩니다.**

## STEP 7. 기사 정보 정리하는 블록 만들기

1. `+` → **Tools > Set multiple variables**
2. `Add item` 으로 변수 5개를 만듭니다

| 변수 이름 | 값 |
|---|---|
| `제목` | `{{get(first(sort(4.array; desc; dateCreated)); "title")}}` |
| `링크` | `{{get(first(sort(4.array; desc; dateCreated)); "url")}}` |
| `본문` | `{{substring(get(first(sort(4.array; desc; dateCreated)); "description"); 0; 4000)}}` |
| `발행일시` | `{{get(first(sort(4.array; desc; dateCreated)); "dateCreated")}}` |
| `중복방지키` | (STEP 6에서 고른 것) |

읽는 법: `sort(4.array; desc; dateCreated)` = 기사들을 **최신순으로 정렬** →
`first(...)` = **맨 앞 1개** → `get(...; "title")` = 그 기사의 제목

### ⚠️ 같은 말을 5번 반복하는 게 맞습니다

"`선택기사`라는 변수를 먼저 만들고 나머지가 그걸 갖다 쓰면 되지 않나?" — 안 됩니다.
Make의 이 블록은 **방금 만든 변수를 같은 블록 안에서 참조하는 걸 보장하지 않습니다.**
번거로워도 5칸 모두 `first(sort(...))` 를 각자 씁니다.

### ⚠️ 왜 굳이 정렬하나

`first(4.array)` 만 써도 대부분 맞습니다. 뉴스는 보통 최신순으로 오니까요.
하지만 그건 **뉴스 사이트의 습관에 기대는 것**이라, 사이트가 정렬을 바꾸면
**아무 에러 없이 엉뚱한 기사가 저장됩니다.** 명시적으로 정렬해두면 그럴 일이 없습니다.

## STEP 8. 이미 저장했는지 확인하는 블록


### 🚨 이 필터는 반드시 AI 요약 블록보다 **앞**에 있어야 합니다

순서가 바뀌면 **이미 저장한 기사에도 AI를 부릅니다.**

대개 **1차에서 끝납니다.** B가 알려준 대로 Make의 `dateCreated`는 이미 날짜 형식이니까요.

# 9. 막혔을 때

| 이런 증상이면 | 원인은 | 이렇게 하세요 |
|---|---|---|
| 필터 뒤 블록이 아예 실행 안 됨 | 통과한 기사가 0개라 흐름이 끊김 | "모으기(Array aggregator)" 블록을 끼웁니다 |
| AI 답변이 빈 값 | 배열 번호를 `[0]`으로 씀 | Make는 **1부터**. `[1]` 로 고칩니다 |
| AI 답변이 글자 덩어리 하나 | Parse response가 `No` | `Yes` 로 바꿉니다 |
| Notion `property does not exist` | 칸 이름 오타 | Notion 화면의 칸 이름과 **한 글자도 다르지 않게** |
| Notion `404 object_not_found` | 통합을 표에 연결 안 함 | 표 페이지 `···` → 연결 → 통합 추가 |
| 9시가 아닌 시각에 실행됨 | 시간대 설정 누락 | 프로필 **과** 조직 둘 다 `Asia/Seoul` |
| 같은 기사가 매일 저장됨 | guid 없는 사이트 + 광고 꼬리표 | 꼬리표 제거 후 해시, 또는 guid 있는 사이트로 교체 |
| 주제와 무관한 기사가 전부 통과 | 필터의 OR가 **그룹을 나눈다**는 걸 놓침 | 제외 조건을 **모든 그룹에** 반복해서 넣기 |
| 중복방지키가 항상 링크 해시로 나옴 | 필드명을 `guid`로 씀 → 빈 값 | Make RSS는 **`id`**. 에러가 안 나니 값을 직접 확인 |
| 중복인데 두 번 저장됨 | Sequential processing 꺼짐 | 시나리오 ⚙ 에서 켭니다 |
| 발행일시가 하루 전으로 보임 | 해외 시간 그대로 저장 | `formatDate(...; "Asia/Seoul")` |
| `python`이 없다고 나옴 | Python 미설치 | python.org에서 설치, **Add to PATH 체크** |
